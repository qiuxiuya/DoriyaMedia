# 账号、注册与权限

一台服务器上可以有很多账号,默认**开放注册**。

## 1. 角色与边界

| 角色 | 能做什么 |
| --- | --- |
| **管理员** `admin` | 全部功能:设置后台(存储源、媒体库、刮削、用户)、扫描、浏览播放 |
| **普通用户** `user` | 浏览、搜索、播放、自己账号的改名改密;**进不了设置后台** |

普通用户**共享全部媒体库**(不按库分权),播放进度按账号各自记录,互不影响。

「后台只有管理员能进」在三层同时生效:

1. **API**:`/api/config`、`/api/sources`、`/api/libraries` 的写操作、`/api/admin/*`
   全部走 `requireAdmin`,非管理员一律 `403 需要管理员权限`;
2. **路由**:前端 `/settings` 带 `meta.admin`,普通用户访问会跳回首页并提示「需要管理员权限」;
3. **入口**:桌面端账号菜单与手机端底部导航对普通用户不显示「设置」。

## 2. 注册的三种模式(设置 → 用户)

| 模式 | 行为 |
| --- | --- |
| **开放注册**(默认) | 登录页出现「注册」页签,注册完立即登录可用 |
| **需要审核** | 注册后账号为 `待审核`,登录会被拒;管理员在设置 → 用户点「通过」才生效 |
| **关闭注册** | 登录页不再显示注册页签;只能由管理员在设置里手动建号 |

同一张卡片里还能设 **密码最短长度**(默认 4,注册 / 建号 / 改密都按它校验)。改完点保存即时生效,
不需要重启。

## 3. 管理员的用户管理(设置 → 用户)

- **用户列表**:角色、状态、创建时间、**上次登录**,当前登录的账号会标出来;
- **添加用户**:直接建号并指定角色(注册关闭时也能用);
- **通过 / 拒绝**:审核模式下的待审核注册单独成区,一眼看到有几个人在等;
- **设为管理员 / 降为用户**:给家人开后台权限,或收回来;
- **禁用 / 启用**:禁用后**已登录的会话立即失效**(不是等他下次登录),播放记录保留;
- **重置密码**:管理员代设新密码(明文显示便于转告),该账号其他设备会被下线;
- **踢下线**:只结束该账号所有设备的登录,不动账号本身;
- **删除**:连带删除该账号的会话与播放记录。

**防呆规则**(服务端与界面同时生效):

- 不能禁用、删除**当前登录的自己**;
- **至少要保留一个可用的管理员**:只剩一个管理员时,不能把他降级 / 禁用 / 删除;
  想卸任,先给另一个人开管理员权限,再降自己;
- 用户名**不区分大小写**:已有 `admin` 时,注册 `Admin` 会被拒,避免出现看着一样的仿冒账号;
- 服务**首次初始化之前**不接受注册,避免陌生人抢在主人之前注册、把初始化流程堵死。

## 4. 账号自助(右上角头像 → 账号设置)

每个用户都能改名、改自己的密码(需要验证当前密码)。改密后**只有当前设备保持登录**,
其他设备需要重新登录 —— 密码泄露时这就是一键止损。

同一处还可以绑定邮箱、连接自己的 Bangumi 账户(见 [媒体库与刮削](library-metadata.md) 第 5 节)。

## 5. 安全细节

- 密码用 **PBKDF2-SHA256**(6 万次迭代 + 每账号随机盐)存储,接口从不返回 hash;
- 会话是随机 token,写进 `HttpOnly` Cookie,默认 **30 天**有效;过期的会话会在下次登录时清理;
- **登录限流**:同一 IP 5 分钟内错 10 次就 `429`,密码正确也要等窗口过去 —— 开放注册后
  登录页谁都能访问,不能让人无限猜;
- **注册限流**:同一 IP 每小时最多 5 次自助注册,防止脚本刷满用户表(管理员手动建号不受限);
- 限流按 **TCP 来源地址** 计,故意不信任 `X-Forwarded-For`(那个头客户端可以自己伪造)。
  挂在反向代理后面时,所有人会共用代理的地址,此时限流按整体计算;
- **存储源的凭据只给管理员看**:`GET /api/sources` 对所有登录用户开放(文件页要列源),
  所以 WebDAV 密码、OpenList 令牌和 B 站 Cookie 在返回给普通用户时被替换成 `******`
  —— 一条 B 站 Cookie 等于一整个账号(含大会员),不能跟着源列表一起发出去。

> 老版本的单账号数据库**无需迁移操作**:首次启动会自动给 `users` 表补上 `status` /
> `last_login_at` 两列,原管理员账号保持管理员身份、可直接登录,媒体库与播放记录不受影响。

## 6. 邮件与人机验证

两件事一起配:**邮箱验证**(证明注册的人真的拥有那个邮箱)和 **Cloudflare Turnstile**
(挡脚本)。都在 **设置 → 邮件与验证** 里,改完即时生效,不用重启。

### 6.1 先配 SMTP

| 项 | 说明 |
| --- | --- |
| SMTP 服务器 / 端口 | 表单上有 **QQ 邮箱 / 163 / Gmail / Outlook** 四个快捷按钮,点一下自动填好 |
| 用户名 | 一般是完整邮箱地址 |
| 密码 / 授权码 | **不是网页登录密码**,而是邮箱设置里生成的「授权码 / 应用专用密码」 |
| 发件人地址 | 留空就用用户名。大多数服务商要求发件人和登录账号一致 |
| 加密方式 | `STARTTLS`(587,默认)/ `隐式 TLS`(465)/ `不加密`(仅本机中继) |
| 发送走代理 | 留空直连。**Gmail 的 SMTP 在国内需要代理**才能连上,填 `socks5://127.0.0.1:7890` |
| 站点地址 | 邮件里链接的前缀。留空按访问者用的地址自动拼;用域名/反代访问时**建议填**,否则链接可能指向内网 IP |

填完点 **测试发送** —— 它会先保存当前填写的内容,再真的连一次 SMTP 发一封信,成功失败都给出具体原因
(连不上 / 认证失败 / 发件人被拒)。**先让测试发送成功,再开邮箱验证**,否则注册的人收不到信。

### 6.2 开启「注册需要邮箱验证」

在 **设置 → 用户 → 注册与登录** 里勾选即可。行为:

- 注册表单多出**邮箱**字段(必填),账号先建好但**不能登录**;
- 系统发一封验证邮件,点里面的链接 → 跳到一个确认页 → 确认后即可登录;
- **老账号完全不受影响**:它们没有邮箱记录,不会因为开了这个开关被挡在门外 ——
  这是刻意的设计,否则一开开关就能把服务器主人自己锁在外面;
- 管理员手动建的账号同样不受影响;想让某人也能自己找回密码,让他到
  **右上角头像 → 账号设置 → 邮箱** 里绑定(或管理员在用户列表里代填,再点「标记已验证」);
- **没配 SMTP 就勾选这个开关**:注册会被明确拒绝(`503 管理员开启了邮箱验证,但服务器还没有配置邮件发送`),
  不会产生一个永远无法登录的账号;登录页也会说明原因。

### 6.3 忘记密码(邮件重置)

登录页的 **忘记密码?** —— 填用户名或邮箱,系统发一封重置邮件:

- 链接 **1 小时**内有效、**只能用一次**;验证邮件是 24 小时;
- 重置成功后,**该账号所有设备都会被退出登录**(包括找回密码前还开着的页面);
- 用户不存在、或没绑邮箱、或已被禁用时,页面**给出完全相同的提示**且不发信 —— 避免被用来探测
  哪些账号存在;
- 跟着链接走完也**顺带证明了邮箱归属**,所以密码重置成功会同时把邮箱标记为已验证。

### 6.4 Cloudflare Turnstile(人机验证)

在 **设置 → 邮件与验证 → Cloudflare 人机验证** 里打开开关,填两把钥匙:

- **Site Key**(公开,给浏览器用)和 **Secret Key**(私密,服务端校验用),都填齐才会生效;
  只填一把等于没开 —— 这样打错字也不会把所有人挡在登录页外面;
- 生效范围:**登录页 + 注册页**。登录时**先验证人机、再校验密码**,所以脚本每猜一次密码都要先过一道验证;
- 免费。去 Cloudflare 后台 → Turnstile → 添加站点即可拿到两把钥匙。

> **两个务必知道的坑:**
>
> 1. **访客的浏览器必须能打开 `challenges.cloudflare.com`**,验证框才显示得出来。国内网络直连
>    通常打不开,需要在客户端侧有代理;打不开时登录页会明确提示「人机验证加载失败」并**禁用提交按钮**,
>    不会让你点了没反应。
> 2. **服务端连不上 Cloudflare 时,登录会被拒绝**(fail closed,不是放行)。如果因此谁都进不去:
>    编辑 `config.json`,把 `"turnstile": { "enabled": true }` 改成 `false`,重启服务即可 ——
>    这是留给你自己的后门。服务端校验请求可以走代理(同一个面板里填)。

### 6.5 安全细节(邮件相关)

- 验证/重置令牌是 32 字节随机数,一次性使用;**同一账号同一用途只保留最新一个**,
  所以点了「重新发送」之后旧邮件里的链接立即作废;
- 邮箱地址**不区分大小写**,同一个邮箱不能开两个账号;
- **发信限流**:同一 IP 每小时最多 5 封(找回密码 / 重新发送合计),
  免得这台服务器被人当成给别人发垃圾邮件的工具;
- SMTP 密码存在 `config.json` 里(和会话密钥同一个文件,那已经是这台服务器的信任边界),
  接口只在管理员请求 `GET /api/config` 时返回。

## 7. 账号相关 API 速查

| 端点 | 权限 | 说明 |
| --- | --- | --- |
| `GET /api/bootstrap` | 公开 | `setup_needed` + 当前注册方式 `registration` / `can_register` / `min_password` |
| `POST /api/setup` | 公开 | 首次初始化管理员(仅在没有任何账号时可用) |
| `POST /api/auth/register` | 公开 | 自助注册;开放模式直接返回会话,审核模式返回 `202 {"pending":true}` |
| `POST /api/auth/login` | 公开 | 登录;被禁用返回 `403`,密码错 `401`,试错过多 `429` |
| `GET /api/auth/me` | 登录 | 当前账号 + `is_admin`,前端据此路由 |
| `PUT /api/auth/profile` | 登录 | 改自己的用户名 |
| `POST /api/auth/password` | 登录 | `{current_password,new_password}` 改自己的密码,其他设备下线 |
| `GET /api/admin/users` | 管理员 | 用户列表(含角色/状态/上次登录,永不返回 hash) |
| `POST /api/admin/users` | 管理员 | 直接建号:`{name,password,role}` |
| `PUT /api/admin/users/{id}` | 管理员 | 改名 / 改角色 / 改状态(`active`、`disabled`、`pending`→`active` 即审核通过) |
| `POST /api/admin/users/{id}/password` | 管理员 | 代设新密码,并让该账号其他设备下线 |
| `POST /api/admin/users/{id}/revoke` | 管理员 | 踢下线(结束该账号所有会话) |
| `DELETE /api/admin/users/{id}` | 管理员 | 删除账号(含会话与播放记录) |
| `PUT /api/config` | 管理员 | 带 `{"users":{"registration":"open\|approval\|closed","min_password":4}}` 切换注册策略 |
| `POST /api/auth/verify-email` | 公开 | `{token}` 消费邮件里的令牌,完成邮箱验证 |
| `POST /api/auth/resend-verification` | 公开 | `{login}` 重发验证邮件;账号不存在也返回同样的提示 |
| `POST /api/auth/forgot-password` | 公开 | `{login,turnstile_token}` 发重置邮件;同样不泄露账号是否存在 |
| `POST /api/auth/reset-password` | 公开 | `{token,password}` 重设密码,并让该账号所有会话失效 |
| `PUT /api/auth/email` | 登录 | 绑定 / 更换自己的邮箱,并发出验证邮件 |
| `POST /api/auth/email/resend` | 登录 | 给自己的邮箱重发验证邮件 |
| `POST /api/admin/mail/test` | 管理员 | `{to}` 用当前 SMTP 配置真发一封测试邮件,失败返回具体原因 |
| `PUT /api/config` | 管理员 | `smtp` / `turnstile` 配置段;`users.require_email` 与 `users.base_url` 也在这里 |
| `GET /api/bangumi/account` | 登录 | 当前用户自己的 Bangumi 连接状态、上次同步与队列统计(不返回令牌) |
| `PUT /api/bangumi/account` | 登录 | `{token}` 验证并保存当前用户的 Bangumi 个人访问令牌 |
| `PUT /api/bangumi/account/settings` | 登录 | `{sync_enabled}` 开关该用户的自动观看同步 |
| `POST /api/bangumi/account/sync` | 登录 | 把本地已看到 90% 的剧集补进同步队列,并重试失败任务 |
| `DELETE /api/bangumi/account` | 登录 | 断开当前用户的 Bangumi,删除令牌与待同步队列(不影响其他人) |

登录与注册在开启人机验证后都要带上 `turnstile_token`;开启邮箱验证后注册还要带 `email`。

## 8. Emby 客户端

支持通过 Emby 协议访问现有账号和媒体库:在客户端手动添加 `http://服务器IP:5666`
(或 `/emby` 路径),用 DoriyaMedia 账号登录,无需另启 Emby 服务。
服务器名称与图标在 **设置 → 系统 → Emby 设置** 里改。

连接方法、安全要求、B 站多流封装和真机验收边界见 [Emby 兼容说明](emby-compatibility.md)。
