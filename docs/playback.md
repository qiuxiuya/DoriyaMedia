# 播放:决策引擎、字幕、不转码

DoriyaMedia 在播放前会先判断「这个文件在这台设备上该怎么播」,然后只挑一种方式去做。
理解这一节能解释绝大多数「为什么这里能播、那里不能播」的问题。

## 1. 为什么需要决策

用 OpenList 挂载天翼云盘时,PC 网页可以直接 302 播放,但 iPhone/iPad 上不行 ——
根因是 iOS Safari 的解码限制:

| 情况 | iOS Safari 能否直接播 |
| --- | --- |
| MP4 + H.264 + AAC | ✅ 可以 |
| MP4 + HEVC(`hvc1` 标签) + AAC | ✅ 可以(硬解) |
| MP4 + HEVC(`hev1` 标签) | ❌ Safari 要求 `hvc1`,黑屏 |
| MKV(任意编码) | ❌ Safari 根本不支持 MKV 容器 |
| EAC3 / DTS / TrueHD 音轨 | ❌ 有画面没声音 |
| 杜比视界 Profile 5 | ❌ 绿紫色花屏 |

## 2. 决策流程

1. 播放前用 ffprobe(对网盘文件走 HTTP Range 远程探测,结果缓存)拿到容器/编码/编码标签/音轨信息;
2. 结合 UA 识别客户端能力(iOS Safari / Chrome 系 / Firefox);
3. **决策**:
   - 客户端原生支持 + 源可出直链(OpenList/网盘)→ **HTTP 302 直连**,流量不经过服务器;
   - 客户端原生支持但源不可直连(本地目录 / WebDAV)→ **代理播放**(支持 Range);
   - 视频可拷但容器/标签/音轨不兼容 → **HLS 转封装**(`-c:v copy`,只把不兼容音轨转成 AAC),
     iOS Safari 用 AVPlayer 原生播 HLS,HEVC 走硬解;
   - 视频编码本身播不了(RMVB / AV1 / 10bit H.264 等)→ **判为无法播放**并说明原因:
     **服务器不再转码**。实时重编码小机器跟不上,与其让观众对着转圈等一个永远追不上的流,
     不如直接说清这个文件在当前设备上播不了。
4. 播放页可以随时手动覆盖决策(强制直连 / 强制转封装)。

**失败后的兜底链**只在客户端**真的能用**的方案里挑,顺序是 直连 → 代理 → 转封装(便宜到贵),
而且不含转码 —— 它不是"更稳的备用", 而是一个服务器已经不做的承诺。
iOS 上容器是 MKV 的片子不会被兜底到 302 直连(那条路必然播不了)。
播放器这边也会先分清楚"服务端还在生成分片"和"这个模式不对":前者重试同一方案,不急着换。

## 3. 探测不再卡住起播(异步 + 预探测)

播放决策必须先探测源文件(容器/编码/音轨),而网盘文件探测很慢。所以:

- **`/api/play` 不再等探测**:没有缓存探测结果时,接口立即返回 `state=probing`
  (含标题与"正在探测媒体信息…"的原因),后台开始探测,前端轮询
  `/api/play/{id}/status`,就绪后再取一次决策。同一文件的探测是**单飞**的
  (多个页面/多次请求只探一次);失败会带原因返回,并冷却 30 秒避免反复打源。
- **探测窗口可配置**:默认 `probe_size_mb=8` + `probe_analyze_sec=4`(旧版固定 50MB/20s)。
  小窗口读不出来的文件会**自动用 50MB/20s 深度探测兜底**,所以不影响识别正确性。
- **扫描后后台预探测**:`preprobe_after_scan`(默认开)会在扫描结束后串行预热新文件的
  探测缓存(`preprobe_max_files` 限量、`preprobe_concurrency` 限并发),这样点开文件
  通常已经是 `ready`,直接出决策。

这几个开关都在 设置 → 刮削与播放 → 播放 里。

## 4. 关于「强制转封装」

转封装只拷贝视频流,所以它只在**该客户端确实能解码这个视频编码**时才生效。
在 AV1 / VP9 / 10bit H.264 这类编码上硬拷只会得到**只有声音、没有画面**(视频流原样拷进去了,
客户端根本解不开),所以现在直接拒绝,并在播放页写明原因
(`手动指定转封装,但 AV1 无法被本机解码(只有声音没有画面);转码已禁用,无法播放`)。

## 5. 关于「不转码」

视频重编码这个能力已经从决策里**整个移除**,不是默认关闭 —— 决策只会在
`302 直连 / 代理播放 / HLS 转封装 / 无法播放` 四者里选一个,`force=transcode` 也不再被接受
(老页面/bookmark 请求它,会落到自动决策)。因此:

- 设置里的「默认播放模式」没有转码选项了,「失败后允许自动改用转码」这个开关也一并删掉;
- 「转码最高高度」改名为**字幕烧录输出高度**:唯一还会重编码画面的地方是**烧录图形字幕**
  (PGS/VobSub 只能叠加),那里仍需限制输出高度;
- 本机解不了的编码(如 AV1、10bit H.264)会明确提示**无法播放**并给出原因,
  播放页只留「返回」,不再有重试/转码按钮;`internal/media/decision.go` 返回 `mode=unsupported`。

HLS 分片是**按需生成**的(每个片段请求时现场 `ffmpeg -ss`,转封装直拷),不写临时文件、
不预转整部片,seek 到哪生成到哪。播放 URL 都带 HMAC 签名,播放器无需带 Cookie。

## 6. 字幕自动载入

字幕**不需要手动选**,打开就自动开。默认选哪一条由**服务端**决定(`/api/play` 里
`default_subtitle_id`,并在该条上标 `default:true`),规则是:中文优先 → 粤语 → 其他已知语言 →
无语言标记的;同语言内**简体优先于繁体**(两者 ISO 代码相同,只能靠标题区分,所以
`简日`/`繁体`/`chs`/`cht` 这类标记会被识别),再按文件内音轨顺序。内嵌字幕轨与同名字幕文件
都参与排序。

客户端拿到 `default` 后自动把该轨切到 `showing`;如果你想固定看某种语言,手动选一次即可,
选择会记在浏览器里(`dm:subPref`)并套用到后续文件。**手动关掉字幕也会被记住**——服务端标的
`default` 不会把它强行打开。

侧挂字幕按需转成 WebVTT,**ASS/SSA 的排版会尽量保留**;内嵌文本字幕轨先让 ffmpeg 转成 ASS
(它保留容器里的样式与定位,而 ffmpeg 自己的 WebVTT muxer 会把两者压平),再走同一条转换。
图形字幕(PGS/VobSub)无法转成文本,只能烧录,不会作为文本轨出现在列表里。

**字幕不再自带黑底**。浏览器画 WebVTT 的默认样式是「白字 + 黑框」,那块黑底正好糊在画面上,
所以全局样式里给 `video::cue` 换成了**透明底 + 描边**(`styles.css`),任何画面上都读得清,
又不挡画面;字幕文件自己要底框的(ASS `BorderStyle 3`)会以 `.dm-box` class 保留下来。
描边粗细可以在播放器的**字幕抽屉**里选 `无 / 细 / 标准 / 粗 / 特粗`,默认 `标准`,选择记在
浏览器的 `dm:subOutline`。这套样式只影响网页里由 `<track>` 绘制的字幕;原生 HLS 字幕和
烧录进画面的字幕不走 CSS,所以不受这项设置影响。

### ASS 转换保留什么

`internal/media/subs.go`:

| 保留 | 形式 |
| --- | --- |
| 结束位置(`\an1`–`\an9`、样式 `Alignment`) | 顶部/中部/底部 + 左中右 → `line:` / `align:` |
| 定位(`\pos`、`\move` 起点) | 画面百分比 → `line:X%,start\|center\|end` |
| 粗体 / 斜体 / 下划线 / 删除线 | `<b> <i> <u>`,删除线走 `.dm-so` |
| 颜色(`\c`、样式 `PrimaryColour`、SRT 的 `<font color>`) | `::cue(.dm-cRRGGBB)` 的 STYLE 块 |
| 底框样式(`BorderStyle 3`) | `.dm-box` |
| 硬换行 `\N` / `\n`、`\h` | 真换行 / 不换行空格 |
| 卡拉OK `\k` | 唱词本身(丢掉逐字计时) |
| 文本里的 `&` `<` `>` 与未知标签 | 转义后原样显示,不会被当成标记吞掉 |

**刻意不保留**:像素级水平定位(WebVTT 的 cue 盒子是按宽度摆的,硬凑像素偏移只会把字挤出画面,
所以水平只分左/中/右)、字号(`\fs` ——会和播放器自己的缩放打架)、以及所有动画与矢量绘制
(`\t`、`\clip`、卡拉OK 扫词、`\p1` 图形——后者的「文字」其实是坐标,现在会被整条丢掉,而不是
把坐标糊到画面上)。

### 底部位置与堆叠

所有原本没有定位的字幕都会被抬到画面底部上方(最底下那条的盒子顶边在 **88%**),
**并且堆叠由服务端自己算**,不再交给浏览器的碰撞处理 —— 交出去的话最底下那条会被放在画面最后一行,
也就是剧场控制栏底下。两个常量都是量出来的,不是猜的:

| 量到的东西 | 值 | 依据 |
| --- | --- | --- |
| 一行字幕占画面高度 | **7.25%** | 800px 高的画面里三条堆叠相距 58px;把画面缩到 400px 高时相距 29px,仍是 7.25% —— 跟的是**画面**而不是窗口 |
| 盒子重叠容差 | **1.5%** | 字形墨迹从盒子顶边往下约 1.6% 才开始、高 4.5%,所以 1.5% 以内的盒子重叠不可能压到字 |
| 底边基准 | **88%** | 按用户给的框定;Chrome 会**忽略 `line:X%,end` 的对齐分量**,按「盒子顶边在 X%」摆放,88% 就是按这种读法选的 |

堆叠规则:按时间顺序,每条字幕放在**它下面所有已放置字幕的最顶边之上**的最低空位(字幕盒子从给的那一行
向下生长,所以它上面那条只需要让开它的顶边,而它自己要给下面那条让出整段高度;换行的字幕因此占两行)。
文件自己用 `\pos` 钉在画面下部的牌子也计入避让 —— 但不会因为零点几个百分点的空隙就把对白顶到画面中部。

**百分比是相对「画面」的,不是相对「播放器元素」的。** 字幕的定位基准是元素盒子,而 `object-fit: contain`
会把画面 letterbox 在元素里 —— 竖屏全屏放 16:9 的片子时,画面只是屏幕中间的一条,上下都是黑边。
这时按元素算出来的 88% 落在画面**下面的黑边里**,看着就是「字幕一直贴着最下方、离画面很远」。
所以播放器会把每条字幕的行位置**换算进画面自己的盒子**(ASS 的坐标本来就是视频空间的),
并且跟着元素尺寸变化重算(靠 `ResizeObserver`,因为 `fullscreenchange` 触发时元素往往还是旧尺寸)。
实测竖屏全屏(390×844,画面 312–532px):字幕盒子顶边落在 505px,相对画面仍是 88%。

**特效字幕想看原样就烧录**:ASS 轨在设置里额外给一个「忠实排版(烧录)」分组(标 `burn_available`),
点它会把字幕叠进画面并重编码(这是唯一还会重编码的路径,输出高度受「字幕烧录输出高度」限制)。
iOS 上这条尤其重要:iOS 用系统播放器渲染 HLS 里的 WebVTT 字幕轨,`line:`/`align:` 这类定位支持有限,
烧录是唯一能保证排版正确的方式。

## 7. 播放页的三种形态与手势

- **桌面 / 手机横屏 = 全屏剧场**:自定义控制条(播放/暂停、±10s、音量、进度拖动与缓冲显示、
  **选集**、字幕、弹幕开关/设置、倍速、画中画、全屏、快捷键 `空格/←→/J K/↑↓/M/F/P/D/0-9`)。
- **手机竖屏 = 竖屏观看页**(YouTube / Bilibili 那种):视频 16:9 在顶部,控制条紧贴视频下方。
- **iPad / 平板**:视频在左上角、控制条在下面,**选集做成右侧侧栏**。
- iOS 无论哪种形态都用**原生播放控件**以保证兼容性。
- **播放手势**:触摸设备上**单击画面不暂停**(手搭在屏幕上太容易误触),单击只把控制条唤回来,
  暂停/播放要点**双击**;桌面端保持「单击暂停 / 双击全屏」。iOS 交给原生控件。

更细的界面说明见 [界面与站点外观](ui-and-site.md)。

## 8. iOS 上的加载判定

**什么时候算"在加载"由播放进度说了算**:只要播放位置在往前走,加载状态立刻消失并且不再回来。
`waiting` 事件不是证据(元素在预缓冲时也会发),**`readyState` 更不是** —— 弱网下
画面明明在动,`readyState` 却可以整部片停在 `HAVE_CURRENT_DATA`(2),因为数据是一片一片
到的。所以判定只看播放位置:它停住(或用户暂停)才显示加载,任何一个 `timeupdate` 推进
就清掉;`canplay`(数据够继续播)也会清一次,这样暂停在缓冲中的观众不会被一直挂着。
这样既不会出现"片子已经在放了,圈还在转",也不会因为圈转久了就弹出「要不要转封装」
—— 那个提示只在画面真的卡住 25 秒后才出现。

## 9. 播放相关 API 速查

| 端点 | 说明 |
| --- | --- |
| `GET /api/play/{fileId}?client=ios&force=auto` | 返回播放决策(模式、URL、字幕、音轨);首次探测未完成时立即返回 `state=probing` |
| `GET /api/play/{fileId}/status` | 探测进度:`idle / probing / ready / failed` + 已用时 + 失败原因 |
| `GET /api/stream/{fileId}` | 302 直连或 Range 代理(带签名) |
| `GET /api/hls/{fileId}/index.m3u8` | 按需生成的 HLS(VOD 播放列表 + 每片段实时 ffmpeg) |
| `GET /api/subs/{fileId}/{subId}.vtt` | 外挂/内嵌字幕转 WebVTT(保留 ASS 定位/颜色/粗斜体;`?start=` 平移到分片会话的时间轴) |
| `GET /api/danmaku/{fileId}/comments.json` | 弹幕(B 站番剧源):`{count, comments:[{t,mode,size,color,text}]}`,按时间排序 |
| `GET /api/img/{itemId}/{poster\|backdrop\|still}` | 海报/背景图 |
| `GET /api/browse/{sourceId}?path=/` | 文件浏览器:列出存储源目录(免建库免扫描) |
| `GET /api/browseplay/{sourceId}?path=...` | 浏览器里点开即播(注册到隐藏库,完整走决策管线) |
| `PUT /api/libraries/{id}` | 编辑媒体库(改名/类型/**路径**/刮削源) |
| `POST /api/libraries/{id}/scan` | 触发扫描;`GET /api/scan/status` 实时返回阶段/目录/文件数/错误 |
| `POST /api/libraries/{id}/scan/stop` | 中止正在进行的扫描 |
| `POST /api/libraries/{id}/subtitle-audit` | 开始字幕体检(只查 bdrip);已在跑时返回 `409` |
| `POST /api/libraries/{id}/subtitle-audit/stop` | 停止体检,已查到的结果保留 |
| `GET /api/subtitle-audit` | 各库体检进度与结果(`?library_id=` 只看一个库) |
| `POST /api/metadata/test` | 用当前/表单里的设置真实请求一次 TMDB 或 Bangumi(`"provider":"bgm"`),测代理/Key/连通性 |
| `POST /api/sources/test-proxy` | 只测一条代理串:`{proxy:"ss://…"}`。经它访问 B 站地区接口,返回 `{ok,country,region,ip,mainland,hmt,latency_ms,message}`;`proxy` 为空则测本机出口 |
| `POST /api/items/{id}/refresh` | 重新识别;可带 `{"bgm_id":328609}` 手动钉住 Bangumi 条目 |
